# Phase 7 — i18n Completeness + PWA-Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or
> superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Follow existing
> conventions (next-intl keys EN+UK, shadcn/ui, mobile-first). This phase has no AI/DB logic;
> it's an i18n sweep + PWA structural readiness. The EN/UK parity check is enforced by a test.

**Goal:** Finish the MVP: (1) every user-facing string goes through next-intl with full EN+UK
coverage (guarded by a parity test); (2) the app is **PWA-ready** — a valid installable web
manifest, icons, standalone display, and mobile/notch polish — so a service worker + web-push
can be added later without rework.

**Scope decision (documented to avoid being mistaken for a gap):** a **service worker /
offline caching / web-push is NOT built this phase** — that belongs to the post-MVP
notifications work. "PWA-ready" here means the *installable manifest + icons + standalone +
mobile viewport* are in place (the manifest/mobile installability checks), and the layout is
structured so an SW can be dropped in later. This matches the spec's "PWA-ready … without
rework."

**Tech Stack:** Next.js 16 (App Router metadata/manifest APIs) · next-intl · Tailwind ·
`sharp` (dev-only, one-time icon generation) · Vitest.

## Task 1: i18n completeness sweep + parity test

**Files:** `src/i18n/__tests__/messages-parity.test.ts`, `messages/en.json`, `messages/uk.json`, plus any component with a stray hardcoded string.

- [ ] **Step 1 (test-first): `messages-parity.test.ts`** — load both JSON files, flatten to dot-paths, assert the sorted key arrays are deeply equal (report any key only-in-EN / only-in-UK). This guards every future change.
```ts
import { describe, it, expect } from "vitest";
import en from "../../../messages/en.json";
import uk from "../../../messages/uk.json";

function keys(obj: Record<string, unknown>, prefix = ""): string[] {
  return Object.entries(obj).flatMap(([k, v]) => {
    const p = prefix ? `${prefix}.${k}` : k;
    return v && typeof v === "object" && !Array.isArray(v) ? keys(v as Record<string, unknown>, p) : [p];
  });
}

describe("i18n message parity", () => {
  it("EN and UK have identical key sets", () => {
    const a = keys(en).sort();
    const b = keys(uk).sort();
    expect({ onlyInEn: a.filter((k) => !b.includes(k)), onlyInUk: b.filter((k) => !a.includes(k)) })
      .toEqual({ onlyInEn: [], onlyInUk: [] });
  });
});
```
  Run it; it should already pass (prior phases kept parity). If it fails, fix the JSON.

- [ ] **Step 2: Sweep for hardcoded strings.** Grep `src/app` and `src/components` for
  user-facing string literals in JSX/attributes that are NOT going through `t(...)` —
  candidates: button labels, headings, placeholders, `aria-label`/`title`/`alt`, empty states,
  toast/error text, the sign-in page, settings labels. For each genuine UI string found, add a
  next-intl key (in the appropriate namespace) to BOTH locales (natural Ukrainian) and replace
  the literal with `t("...")`. Do NOT churn non-UI strings (test fixtures, enum *values* stored
  in the DB like `"vip"`/`"family"`, log/throw codes, class names, data attributes).
  Suggested grep starting points:
  - `rg -n '>[A-Z][a-zA-Z ]{2,}<' src/app src/components` (JSX text)
  - `rg -n '(placeholder|aria-label|title|alt)="[^"]*[a-zA-Z]{3,}' src/app src/components`
  Review each hit; many will already be `t(...)` calls — only fix true literals.

- [ ] **Step 3:** Re-run `pnpm test` (parity test green) + `pnpm lint`. Commit:
  `feat: i18n completeness sweep + EN/UK parity test`.

## Task 2: Web manifest + icons + mobile/standalone polish

**Files:** `public/icons/*`, `scripts/generate-icons.mjs`, `src/app/manifest.ts`, `src/app/layout.tsx`, `src/components/bottom-nav.tsx`

- [ ] **Step 1: Source mark + icon generation.** Create `public/icons/icon.svg` — a simple,
  on-brand mark (e.g. a rounded-square background in the app's theme color with a centered
  monogram "E" / a simple relationship/connection glyph; keep it clean, no external fonts —
  use a basic system serif/sans path or a simple geometric shape). Then `scripts/generate-icons.mjs`
  using `sharp` to render the SVG to PNGs:
```js
import sharp from "sharp";
import { readFileSync } from "node:fs";
const svg = readFileSync("public/icons/icon.svg");
const out = [
  ["public/icons/icon-192.png", 192],
  ["public/icons/icon-512.png", 512],
  ["public/icons/apple-touch-icon.png", 180],
];
for (const [path, size] of out) {
  await sharp(svg, { density: 384 }).resize(size, size).png().toFile(path);
}
// maskable: same art with safe padding already in the SVG (or a padded variant)
await sharp(svg, { density: 384 }).resize(512, 512).png().toFile("public/icons/icon-maskable-512.png");
console.log("icons generated");
```
  Install + run once: `pnpm add -D sharp && node scripts/generate-icons.mjs`. Commit the
  generated PNGs (so production/CI doesn't need sharp at build). Verify each PNG exists and is
  a valid image (non-zero size, correct dimensions — `sharp(path).metadata()` or `file`).
  NOTE: the maskable icon needs ~20% safe padding around the mark so it isn't clipped by the
  circle/squircle mask — bake that padding into the SVG (or a maskable variant) so the monogram
  isn't cut off.

- [ ] **Step 2: `src/app/manifest.ts`** (Next.js `MetadataRoute.Manifest`):
```ts
import type { MetadataRoute } from "next";

export default function manifest(): MetadataRoute.Manifest {
  return {
    name: "Emmanuil",
    short_name: "Emmanuil",
    description: "Your relationship portfolio + AI assistant",
    start_url: "/",
    display: "standalone",
    background_color: "#ffffff",       // match the app theme
    theme_color: "#ffffff",            // match the app theme
    icons: [
      { src: "/icons/icon-192.png", sizes: "192x192", type: "image/png" },
      { src: "/icons/icon-512.png", sizes: "512x512", type: "image/png" },
      { src: "/icons/icon-maskable-512.png", sizes: "512x512", type: "image/png", purpose: "maskable" },
    ],
  };
}
```
  (Pick `background_color`/`theme_color` to match the shadcn theme actually in `globals.css` —
  read the `--background` token; use its resolved color, not a guess.)

- [ ] **Step 3: Layout metadata + viewport + apple meta** (`src/app/layout.tsx`): add Next's
  `export const viewport: Viewport = { themeColor: "...", width: "device-width", initialScale: 1, viewportFit: "cover" }`
  (the manifest is auto-linked by Next from `app/manifest.ts`; confirm, else add it to
  `metadata`). Add apple web-app metadata via the `metadata` object:
  `appleWebApp: { capable: true, statusBarStyle: "default", title: "Emmanuil" }`, and
  `icons: { icon: "/icons/icon-192.png", apple: "/icons/apple-touch-icon.png" }`. Keep the
  localized `<html lang={locale}>` already in place.

- [ ] **Step 4: Safe-area / standalone polish.** In `bottom-nav.tsx`, add bottom safe-area
  padding so the nav clears the home indicator in standalone mode, e.g. add
  `pb-[env(safe-area-inset-bottom)]` to the nav container (and ensure the main content's bottom
  padding accounts for the nav height + safe area). Verify nothing overlaps on a small viewport.

- [ ] **Step 5:** `pnpm build` + `pnpm lint` green. Smoke: `pnpm dev`, then
  `curl -s localhost:3000/manifest.webmanifest` returns valid JSON with the icons, and
  `curl -sI localhost:3000/icons/icon-512.png` returns 200 `image/png`. Stop the server.
  Commit: `feat: PWA web manifest, icons, and standalone/mobile polish`.
