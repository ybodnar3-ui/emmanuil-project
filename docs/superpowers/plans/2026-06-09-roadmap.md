# Emmanuil — Implementation Roadmap

> Phased build. Each phase produces working, testable software and is committed
> separately. We detail and execute one phase at a time; the next phase is detailed
> only after the previous one is done (its details depend on real code, not guesses).

**Spec:** [../specs/2026-06-09-personal-crm-design.md](../specs/2026-06-09-personal-crm-design.md)
**Repo:** https://github.com/ybodnar3-ui/emmanuil-project

**Tech stack:** Next.js (App Router, TS) · Tailwind + shadcn/ui · Supabase
(Postgres/Auth/Storage) · Prisma · Anthropic Claude API · Web Speech API · next-intl ·
Vercel.

## Prerequisites (gathered as phases need them)

These are external accounts/keys. We will only need each when its phase starts, so they
are not blockers for Phase 1 (which runs fully local).

- **Supabase project** (URL + anon key + service role key + DB connection string) — needed Phase 2.
- **Anthropic API key** — needed Phase 4.
- **Google OAuth client** (optional, magic-link works without it) — Phase 2.
- **Vercel project** — needed for deploy (any phase, optional until launch).

## Conventions (all phases)

- **TDD where it fits.** Logic (prompt building, extraction parsing, cadence math, RLS) is
  test-first. Pure scaffolding/UI wiring uses verification gates (build/lint/dev render).
- **Frequent commits.** Each task ends with a commit; each phase ends with a push.
- **Commit style.** Conventional commits (`feat:`, `chore:`, `test:`), co-authored trailer.
- **i18n from day one.** No hardcoded user-facing strings — always translation keys.
- **Per-user isolation.** Every data access is scoped to the signed-in user (RLS + query scoping).
